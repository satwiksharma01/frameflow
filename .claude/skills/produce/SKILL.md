# A video from a prompt, with you as the editor

Frameflow does the mechanical work: transcribing recordings, reading the voiceover, rendering titles and captions with HyperFrames, turning images into clips, building the project, studying each clip and the finished video for you to look at. You decide what the video is, and Frameflow's roll keeps its look off the category default. The user approves four times: the brief, the direction, the storyboard, and the fixes your look at the built video finds.

1. **Prepare.** Pick a folder under `output/` named for the video. From the repository root, pass the user's prompt in their own words and everything they gave you:

   ```
   python -m project.produce output/<name> --prepare "<prompt>" [--script FILE] [--footage VIDEO ...] [--asset FILE ...] [--music FILE ...] [--look LUT ...] [--project SLUG]
   ```

   Give each kind once, followed by all its files: `--asset A B C`, not `--asset A --asset B`. When the user works in a project (their channel, page or series in `projects/`), pass `--project <slug>`: its catalog of worlds then leads the direction, and its brand kit is used. `--look` takes the user's own colour LUTs (`.cube` files) to choose the video's look from; OpenShot's own are offered either way.

   If it stops on a recording with "no usable speech", tell the user the measured numbers and stop. When the message says the clip may have no talking, suggest passing it with `--asset` (a picture or clip) instead of `--footage`.

2. **Describe the clips.** When prepare names `eyes/shots_request.md` instead of the brief's request, read it in full and open each clip's sheet: its frames with their times. Where a sheet is too coarse to see when something happens, take the closer look the request shows (`python -m project.eyes sheet …`, four frames a second). Write `eyes/moments.json`, each clip's moments in order, then run `python -m project.produce output/<name> --shots` and fix what it reports. It writes the brief's request with a shot list: one line per moment.

3. **Brief.** Read `brief_request.md` in full and write `brief.json`, with its `mode`: what success is for the viewer (`creative/modes.md`). For a pitch, or any video that states facts about the world, research them with your web tools as the request says: each with who says it, its page, and the exact words on that page. Run `python -m project.produce output/<name> --brief` and fix what it reports. Show the user the brief in plain words - what the video is, for whom, how long, which shape - with any open questions, and each fact with its source and link, marking any Frameflow could not open for them to check. **Wait for them to confirm.** Put their answers into `brief.json` and remove `open_questions`.

4. **Direction.** A committed look for this video, before its storyboard. Each run of `python -m project.produce output/<name> --direction` does the next thing:
   1. Run it, read `direction/request.md` in full (and the `creative/` files it names), and write `direction/candidates.json`: the framing, and the seven candidates when it asks for them.
   2. Run it again: Frameflow rolls. Read `direction/hand_request.md` in full, read the world files it names, and write `direction/hand.json`.
   3. Run it again and show the user the hand it prints, as it prints it. **Wait for them to choose, re-roll or pin.** Then run `--choose <card id>`, `--reroll [plain|safer|bolder]` (and go round again from 1), or `--pin "<their words>"` (then write `direction.json` as the request asks).

   Skip the step when the user is making it like a reference video (below), or asked for the plain standard: then `--choose standard` from a hand.

5. **Storyboard.** Run `python -m project.produce output/<name> --storyboard`, read `storyboard_request.md` in full and write `storyboard.json`. With a direction, its Direction section is a contract: follow it, make the first two seconds as written, and list after the script whatever it asks that the storyboard cannot say yet. Choose each clip's scenes from its moments in the shot list, by their times, and a closer look where a moment's edges matter. Footage spans start and end inside the measured pauses listed for each recording. End a span in a pause of at least a quarter of a second where there is one: the build leaves the last word heard that much room, and a shorter pause right after a word can be the silence inside its last sound, before a final "k" or "t". Show the user the script, each scene in one line (what is seen, what is said, any caption, card or B-roll), whether what is said is shown as word-by-word captions (`spoken_captions`), whether the cuts land on the music's beat (`cut_to_beat`), and the look, if any (`look`: which LUT, and how strongly), and what any `generated` picture or clip would cost. **Wait for them to confirm**, and change it as they ask.

   **Made like a reference video** the user gives you (a reel, a short, an ad they want theirs to be like), the storyboard comes from Agent Video instead. Run `python -m project.produce output/<name> --reference "<video>"`, read the `analysis-request.md` it names in full, look at the reference's frames and contact sheet and listen to it as the request says, and write `analysis.json` and `concepts.json` beside it: what you observed, each with the stretch of the reference that shows it, or "unknown"; and two or three concepts that keep its structure with the user's own material. Run `--concepts` and fix what it reports. Show the user what you found and the concepts, and **wait for them to pick one**. Run `--concept <id>`; with `--sample 10` it is only the opening scenes, to build and look at first. Show that storyboard as above and wait for them to confirm. Agent Video adds no narration. What its storyboards cannot say - a tier list or banner that stays up under the speaker, pictures popping up as things are said - write as one HyperFrames composition and add it to `storyboard.json` as its `overlay` after `--concept`; snapshot it with `npx hyperframes@0.8.199 snapshot <folder> --at <seconds> --describe false` before building (`--describe false` keeps it from sending frames to Gemini when a key is set).

6. **Build.** Run `python -m project.produce output/<name> --build --open`. If it reports problems, fix `storyboard.json` and run it again until it succeeds. If the storyboard has `generated` scenes and the build stops over the cap, tell the user what each costs and add `--budget <dollars>` only once they say so.

7. **Look.** Run `python -m project.produce output/<name> --look-at`, read `look/request.md` in full and open `look/sheet.jpg`: the built video's frames, the first two seconds closely and every scene's first frame. Judge it as the request says, against the direction too when there is one, write `look/look.json`, and run `--look-at` again. Show the user the verdict and each finding. **Only with their OK**, fix through `storyboard.json` and build again; two rounds at most, then the user decides.

8. **Report.** Tell the user the length against the brief, what is on each track, anything the build flagged with `!` in the picture, and that it is an ordinary project: they can change it in OpenShot, or ask for changes in words (the edit skill).
